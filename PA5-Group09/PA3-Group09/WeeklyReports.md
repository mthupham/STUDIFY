# Sprint Review

### What Went Well

* The team successfully completed the basic Authentication functionality.
* User profile information can now be stored successfully.
* The frontend implementation of Function 2 – Self-Study Dashboard was completed.
* The excessive zoom issue in the Placement Test interface was successfully fixed.
* The team clearly divided responsibilities for PA3 and Function 2.
* The team identified the main integration issues early enough to prioritize them before the deadline.
* The team maintained communication and continued development despite the midterm examination period.

### What Went Wrong

* The Forgot Password functionality could not successfully send recovery emails.
* Backend and frontend integration for lesson content was not completed on time.
* The progress of the previous week was slower than expected because several team members had midterm examinations.
* Some UI issues required additional rework and refinement.
* The backend implementation of Function 2 was behind the completed frontend implementation.

### Problems and Causes

| Problem                                               | Cause                                                                                             |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Forgot Password emails could not be sent successfully | The email recovery functionality was not fully configured or integrated.                          |
| Lesson content could not be displayed on the frontend | The backend APIs and frontend interfaces were not fully connected.                                |
| Development progress was slower than planned          | Multiple team members had midterm examinations during the previous week.                          |
| Some UI components required rework                    | Some initial UI implementations did not meet the expected visual quality or scaling requirements. |
| Backend progress was slower than frontend progress    | Backend Function 2 implementation and API integration were still in progress.                     |

### What Can Be Done Differently in the Next Sprint

* Start backend and frontend integration earlier instead of waiting until the frontend is fully completed.
* Prioritize API development based on the frontend implementation schedule.
* Conduct integration testing continuously throughout the sprint.
* Allocate buffer time for bug fixing and unexpected technical issues.
* Communicate blockers earlier so that tasks can be reassigned when necessary.
* Reduce the impact of academic commitments by planning critical tasks earlier.
* Conduct more frequent progress reviews when approaching the project deadline.

### Lessons Learned

* Frontend and backend development should progress in parallel with clearly defined API contracts.
* Integration should be tested continuously rather than being postponed until the end of the sprint.
* Tasks involving external services, such as email delivery, should be tested early.
* Clear task ownership helps the team identify responsibility for both implementation and documentation.
* The team needs to account for academic commitments when estimating sprint capacity.
* Early identification of blockers allows the team to respond more effectively and avoid last-minute delays.
